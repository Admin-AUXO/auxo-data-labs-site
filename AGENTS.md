# Working in this repo

Marketing site for AUXO Data Labs. Astro 6 + TypeScript + Tailwind v4, deployed to Netlify (custom domain `auxodata.com`).

Audience: sceptical founders, finance leads, operators and team heads at startups (seed to Series B), growing companies (50–500 people) and large organisations in the UAE, the US and Europe. They skim, compare, then contact only once the page earns trust. Build for clarity, not animation noise or client-side bloat.

## Stack

- **Astro 6**, fully static (`output: 'static'`, no adapter), view transitions via `ClientRouter`. Every route prerenders. The Founder review application (`/apply/`, old `/contact/` redirects) and the AUXO Score email step post to the Netlify function `netlify/functions/lead.mts` (`/api/lead`), which appends a row to the pipeline sheet tab "Inbound", upserts the contact in Sequenzy and sends the Score report or applicant confirmation from hello@auxodata.com. Other functions: `followups.mts` (daily nurture week), `spots.mts` (`/api/spots`, 10 Founder reviews a week), `pay.mts` and `pay-confirm.mts` (Stripe deposit for a proposal, pages `/pay/` and `/pay/thanks/`). Shared code in `netlify/lib/`. See `docs/lead-pipeline.md`. Netlify auto-deploys `main`; deploy config, redirects and headers in `netlify.toml`. `.github/workflows/staging.yml` publishes every push to https://staging.auxodata.com (GitHub Pages, noindex, no functions).
- **Tailwind v4**, CSS-first (`@import "tailwindcss"`). Tokens in `src/styles/tokens.css` are the source of truth.
- **Pagefind** search (lazy-loaded), **astro-icon**, **MDX** for blog and insights, **astro-og-canvas** for OG images. GTM/GA4 load deferred (first interaction or 2.5s post-load) with inline Consent Mode v2 — keep it off the critical path. GTM container ID comes from `src/config/env.ts`.
- Single dark theme, lime accent. Self-hosted `woff2` fonts in `public/fonts/`: headings **AUXO Display** (Mona Sans, OFL, instanced at width 112 and renamed per its Reserved Font Name; licence `AUXODisplay-OFL.txt`), body **Plus Jakarta Sans**, mono **JetBrains Mono**, logo **Montserrat AUXO**. Heading weights 800/700 come from the `--font-weight-display-strong` / `--font-weight-display` tokens.

## Layout

- `src/pages`, `src/layouts`, `src/components` — routes and composition
- `src/data` — page copy (edit content here, not in templates)
- `src/lib` — AUXO Score logic (`src/lib/auxo-score/`), blog and structured-data helpers
- `src/scripts` — browser behaviour; analytics in `src/scripts/analytics/`
- `src/styles` — tokens + layered CSS via `main.css`; page CSS in `src/styles/pages/`
- `src/content/insights` — MDX insight cards
- `src/content/blog` — MDX blog posts
- `public` — static files shipped as-is (icons, fonts, vCards, crawler txt files). `manifest.json`, `sw.js` and `llms-full.txt` are generated by routes in `src/pages`.
- `docs/` — AUXO Score, lead pipeline and Wallet pass notes

## Rules

- Default to static markup. Add a client `<script>` only where the interaction is real.
- Follow the existing structure before adding abstractions. Edit copy in `src/data/*.ts`.
- The codebase is comment-free: add no code comments (the `src/env.d.ts` `///` directive is the only exception).
- The `astro-icon` allowlist in `astro.config.mjs` is exact — add an icon name there before using it, or the build fails.
- Page-only CSS belongs in that page's frontmatter import, not global `main.css`.
- View transitions are on, so bundled scripts run only once per full page load: initialise on `astro:page-load` (fires on first load and after every navigation) and clear timers on `astro:before-swap`. `src/layouts/BaseLayout.astro` re-applies `data-js` and `data-motion` on `<html>` in `astro:after-swap`; don't set those elsewhere.
- Motion is on by default for every visitor (the OS reduced-motion setting is not used) and switchable via the footer toggle (persisted in localStorage via `src/scripts/core/motion.ts`). Rich motion only runs under `html[data-motion="on"]` — gate any new animation behind it and read `motionEnabled()` in JS.
- Push analytics events with `track()` from `src/scripts/analytics/track.ts` (AUXO Score events go through `scoreEvent()` in `src/lib/auxo-score/analytics.ts`). A new event needs a trigger and tag published in GTM `GTM-5TKFHDH5` before it reaches GA4.
- `public/` bypasses the build pipeline — keep it standards-based and self-contained.
- Section pattern: eyebrow + heading + lead stacked (`SectionHeader`) over a full-width grid. Headings are two-tone: the second sentence is muted via `HighlightText soften`; `.hl-accent` is the accent colour. The home hero is text-only.
- `Accordion` hides item numbers when it has three items or fewer.

## Content

- One job per page. No generic awareness copy.
- Lead with the buyer's problem, deliverables, and proof — not vision language.
- Write for skimmers: headings and first sentences carry the argument.
- Plain language, no jargon, no invented metrics.
- Analyze has three depths, named the same everywhere: **AUXO Score** (self-check, anyone), **Founder review** (30-minute founder call by application, every segment, 10 a week, written next steps, no charge) and **Deep-dive audit** (paid systems review). Large organisations start with **One unit first**. Every AUXO Score taker sees the same report. No public prices: "a fixed price per phase, in writing". Don't add "free" as filler.
- Blog posts show no author names.
- Two CTAs only: "Apply for a Founder review" (primary, `/apply/`) and "Take the AUXO Score". Cold content (blogs, teaser) carries the Score only.

## Commands

## Done means

- Run the narrowest check that proves the change: `npm run lint` for code edits, `npm run build` for layout/routing/`public/` changes, `npm run test:unit` for AUXO Score logic, `npm run validate` for repo-wide work.
- For layout or page-composition changes, also check desktop and mobile in the browser.
- State what you verified and what you did not.
