A working system with no readable documentation is a single point of failure. It runs until the one person who understands it moves on. Handover isn't done when the code runs or the agent sends its first draft. It's done when someone on your team can change it from the written word alone. Write it plainly, for the people who will run it day to day: what it does, where the data comes from, who approves what, and how to change a rule. That document is the difference between a capability you keep and one that leaves.

Where this fits: [Build](/how-it-works/). Plain-English documentation and training, so the know-how stays with your team.
