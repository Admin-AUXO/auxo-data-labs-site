**In short:** an AI agent may read and draft without approval. Anything that changes your systems needs a review. Anything that sends, posts, pays or hires needs a named person to approve it every time.

Say someone on your team wants to try an AI agent on Monday. It can read the shared inbox, update the CRM and draft replies to customers and investors. Nobody has said what it may do without asking.

Close that gap before you build.

## Three tiers of action

Sort every action by what it touches. Two published guides make the same point. Anthropic's guide to [building effective agents](https://www.anthropic.com/research/building-effective-agents) says agents can pause for human feedback at checkpoints. OpenAI's [practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) names high-risk actions, meaning sensitive, irreversible or high-stakes ones, as a trigger for human intervention. Its examples include cancelling orders, authorising large refunds and making payments.

**Tier 1: read and draft.** The agent reads documents, summarises, sorts, checks and flags. It writes drafts nobody has seen yet. No approval is needed. Spot-check a sample.

**Tier 2: change something inside your own systems.** The agent updates a CRM record, moves a ticket, changes a status, files a document. Most can be undone. Either a person approves them, or the agent writes each change to a review log that a named person reads on a set day. Pick one and write it down.

**Tier 3: act on the outside world.** Send, post, pay, sign, hire. A named person approves every one, every time. A sent investor email cannot be unsent.

## Five questions before any agent goes live

This takes an hour with the process owners. If you cannot answer one, the agent is not ready.

1. **What can it read?** List every mailbox, folder, database and file store. Customer data and confidentiality problems start here.
2. **What can it change?** List every record, field and setting it can write to. Mark which changes are reversible.
3. **What can it send outside?** Email, messages, posts, payments, API calls to other firms. Each is a Tier 3 action.
4. **Who approves?** One name or role for each Tier 3 action, plus cover for holidays. If nobody responds, nothing goes out.
5. **How do you see what it did?** If you cannot replay a run, you cannot fix a mistake or explain it to a customer.

The [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) is voluntary guidance for managing AI risk to people, organisations and society. It is a useful frame if your board or insurer asks how you assess risk. These five questions are a start inside it.

## Access and logs

Give the agent the least access that does the job. Start with read-only and add write access one permission at a time.

Run it under its own account, never a person's login. Its actions are then labelled, and you can remove its access without locking out a colleague. Decide who can switch it off, and make sure they can do it in minutes.

Keep a log of every run: what it was asked, what it read, which tools it used, what it produced and who approved it. [Agents in practice: tools and approvals](/blog/agents-in-practice-tools-and-approvals/) covers what a good trace holds.

## Test before launch

Test in a sandbox with copies of real data, not live systems. Anthropic recommends extensive testing in sandboxed environments along with appropriate guardrails, because errors can compound over many steps.

- **Normal and messy cases.** Twenty ordinary examples, then missing fields, odd formats and duplicates.
- **Hostile text.** An email or document that tells the agent to ignore its rules. It should flag the text, not obey it.
- **Boundary tests.** Ask it to send, pay or delete something. It should stop and ask for approval every time.
- **Approver test.** Does the approver see the source next to the draft, and can they reject with one click?
- **Switch-off test.** Turn it off during a run. Confirm nothing half-finished is left behind.

## When the agent gets it wrong

It will, eventually. Plan for it now.

**Stop it.** The named person switches it off first and investigates second.

**Contain it.** Use the log to find every action in the affected period. Reverse what can be reversed. Contact anyone who received something wrong.

**Find the cause.** Was it bad input, a missing rule, too much access or an approver who did not look closely?

**Change the tier.** If an action keeps going wrong, move it up a tier.
