**In short:** An agent is a model that can [use tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview): search a database, read a file, draft an email, update a record. Every tool is a permission. Start with the simplest setup, grant tools by risk, and name who approves before you build.

## Who signs off on this?

Say your finance lead has a stack of supplier invoices on the desk and wants an agent to help match them to purchase orders. Before anyone talks about models, someone should ask a plainer question. If it gets one wrong, who sees it first?

That question shapes the whole build. So we start there, then pick the model.

## Which model for agent work?

All current Claude models can use tools. Anthropic's guidance gives each a different role.

- **Fable 5.2** is positioned for long-running agent work, such as sessions that run for hours or multistep research carried through to a finished document.
- **Opus 5.5** is built for long-running coding and knowledge work, and is Anthropic's suggested starting point for most workloads.
- **Sonnet 5.5** handles everyday tool use well. For well-specified multistep tasks, Anthropic suggests starting at medium effort and moving to high for harder or longer ones.
- **Haiku 5.5** suits short steps inside a larger agent, such as a sub-task that sorts or extracts.

[Effort](https://platform.claude.com/docs/en/build-with-claude/effort) matters here too. Anthropic notes that lower effort means fewer and shorter tool calls. That saves money. But on Haiku at low effort, a long agent task is more likely to skip a search or a check. For agent work, measure before you lower it.

## Start with less than you think you need

Anthropic's guide to [building effective agents](https://www.anthropic.com/research/building-effective-agents) makes a point worth repeating. Start with the simplest setup that works. Many tasks need a fixed sequence of steps, not an agent that decides for itself. Agents trade higher cost and slower responses for flexibility, and their errors can compound.

A fixed workflow is easier to test, cheaper to run and easier to explain to an investor or auditor. Use an agent only where the steps genuinely vary.

## Grant tools by risk

Look at each tool in three ways.

- **Read or write.** Reading a ticket queue is low risk. Writing to a payment system is not.
- **Reversible or not.** A draft can be deleted. A sent email cannot be unsent.
- **Impact.** Changing a label is small. Changing a price, a payment or a contract is large.

Start with read access. Add write access only where the task needs it. Nothing irreversible happens without a person.

<Callout>
Every tool you grant is a permission, so grant them by risk and keep a person at the irreversible steps.
</Callout>

## Decide the approval points first

Build them into the workflow itself, not into a policy document nobody reads. In each case below, the agent drafts, sorts, checks and flags, and a named person approves what goes out.

**Finance.** The agent matches invoices to purchase orders and flags mismatches. A person approves every payment. It also drafts the monthly investor update from your metrics, and a founder reads and sends it.

**Sales.** The agent researches an account and drafts a follow-up in your CRM. The owner of the deal edits and sends it.

**Support.** The agent reads a ticket, finds the relevant help article and drafts a reply. A support lead approves refunds and anything that promises a fix.

**Engineering.** The agent triages bug reports and opens a draft fix. An engineer reviews and merges. Nothing reaches production without that review.

## Keep a record

For every run, keep a trace: what the agent was asked, what it read, which tools it used, what it produced, and who approved it. When something goes wrong, and eventually something will, you need to be able to replay it.

## Try this

Pick one task you would like an agent to help with. List every action it would need to take. For each one, mark:

1. Read or write.
2. Reversible or not.
3. Who should approve it, if anyone.

If more than half the actions are irreversible writes, start with a fixed workflow that drafts and hands over, not a free-running agent. If most are reads, you have a good first candidate.
